## Project Overview

**Requested Grant Amount (USD):** $9,081.20

**Category:** Infrastructure / Community Tooling

**Project Summary**
Gleyo is a Zcash-native community growth platform that enables any online community to reward contributors directly in shielded ZEC, making Zcash onboarding a natural outcome of community participation rather than a prerequisite.

**Project Description**
Gleyo lets project owners fund a community wallet with ZEC (or USDT/USDC, auto-converted to ZEC via NEAR Intents/Defuse Protocol), create quests with XP and/or ZEC rewards, and review member submissions, while giving owners real retention analytics (7d/30d/90d active members, dropoff percentage, growth signals) instead of the vanity social metrics offered by platforms like Zealy.

The core design decision that separates Gleyo from every other quest platform is who it's built for: not the Zcash-native user, but the newcomer. Community members can earn ZEC without ever connecting a wallet upfront, removing the single biggest barrier to entry for newcomers unfamiliar with Zcash or shielded transactions. This means a person's first experience with Zcash can be "I completed a task and received private money," rather than "I need to learn what a shielded transaction is before I can participate." That is a fundamentally different, and lower, on-ramp than anything else currently serving the ecosystem.

Since launching during ZecHub Hackathon 2026 (July 14, 2026), Gleyo has grown to 38 weekly active users in closed beta, processed real mainnet ZEC deposits and withdrawals, redesigned its withdrawal architecture into a queued system to safely support concurrent multi-community activity, shipped multi-token (USDT/USDC) funding following a suggestion from ZecHub PR reviewer @squirrel, and successfully verified full end-to-end compatibility with the July 28, 2026 Ironwood network upgrade across both direct shielded-wallet deposits and stablecoin-to-ZEC swap deposits.

**Technical Approach**
Gleyo's production infrastructure is intentionally split across multiple services to isolate responsibilities and reduce risk. Cloudflare fronts the application, providing DNS, TLS termination, caching, and DDoS protection before traffic reaches the Flask backend running on AWS EC2. The application uses Flask with SQLAlchemy, PostgreSQL on AWS RDS for persistent data, Redis as the server-side session store (with automatic filesystem fallback if unavailable), and Supabase for object storage.

All shielded ZEC functionality is isolated from the application tier. The Flask backend communicates with the Nozy Wallet API (developed by LEONINE DAO), which runs on a separate Contabo VPS alongside a self-hosted Zebra full node. This separation keeps wallet infrastructure independent from the web application while providing direct access to the Zcash network without relying on third-party lightwalletd services.

Wallet authentication uses a shielded micro-transaction containing a session code in the memo field, while deposits, balance synchronization, and withdrawals are handled entirely through Nozy. Withdrawals are routed exclusively to Unified (u1) addresses through Nozy's transaction API.

Security is layered throughout the deployment. The Nozy API is not publicly exposed to the internet; UFW firewall rules restrict access exclusively to Gleyo's EC2 instance, with authenticated API requests providing an additional security layer. Nozy communicates with Zebra over RPC for balance synchronization, deposit verification, and shielded transaction broadcasting, while Zebra maintains its own peer-to-peer connection to the Zcash mainnet. External integrations, including GitHub, Discord, Telegram, YouTube, email delivery (Resend/SMTP), and NEAR Intents (Defuse Protocol) for USDT/USDC-to-ZEC funding, operate as independent outbound services, ensuring failures in third-party providers do not interrupt Gleyo's core platform.

During Ironwood migration testing (July 28, 2026 network upgrade), this dependency on Nozy surfaced a production-breaking Axum routing incompatibility. I diagnosed and fixed the issue, merging the fix upstream to LEONINE-DAO/Nozy-wallet (PR #180), restoring Ironwood pool deposit compatibility for Gleyo and every other project depending on Nozy's API layer.

Separately, in the course of operating Gleyo's withdrawal pipeline, I diagnosed a pending-transaction reconciliation issue in Nozy where certain withdrawal attempts would surface as failed on the client side despite the underlying transaction later confirming, caused by a balance/state sync gap between Nozy and Gleyo's polling logic. I traced this to its root cause and worked with the Nozy team on a fix, improving reconciliation reliability for Gleyo and any other project consuming Nozy's transaction status API.

Beyond Nozy, testing and building Gleyo has surfaced real issues on other Zcash ecosystem projects as well. While testing Dizzy, I reported a validation bug where Orchard-only Unified Addresses were incorrectly rejected as invalid despite passing correct Bech32/Bech32m checksum validation; the dismad team confirmed and worked with the developer on a fix. While testing LiveZEC (zec.live), a private ZEC donations platform for streamers, I reported two UX issues: an account-deletion 2FA requirement that lacked explanatory context, and a "Set up your Viewing Key" modal that kept re-triggering on page navigation; both were addressed by the LiveZEC team following the reports.

**Note on Nozy-related contributions:** This application is entirely separate from the retroactive grant application already submitted by LEONINE DAO/Nozy Wallet for their own work. The Nozy PR #180 and reconciliation fix referenced above are unpaid contributions I made to Nozy specifically because Gleyo depends on its API, and are cited here only as evidence of technical skill and ecosystem impact. My requested compensation covers hours spent building Gleyo itself; it does not claim any hours tied to Nozy's own development, and there is no overlap between this request and Nozy's separately submitted application.

**Path to Self-Sufficiency**
Gleyo operates a Free and Pro tier model. Zcash-native projects, communities, and creators remain free on Gleyo permanently, including premium collaboration features such as community analytics and engagement insights, ensuring no Zcash builder is ever gated behind a paywall to grow their community. Revenue is instead generated by offering the Pro tier to communities and projects outside the Zcash ecosystem who want the same quest, retention-analytics, and ZEC-reward tooling for their own communities, with initial Pro tier pricing planned in the $60–100/month range, notably below comparable platforms such as Zealy ($250–500/month), positioning Gleyo as the more accessible option for external adoption. This mirrors the sustainability model already outlined in Gleyo's parallel ZCG application: monetizing external demand to fund ongoing development and infrastructure costs, rather than relying on continued grant funding or monetizing the Zcash community itself. As Gleyo's user base grows beyond closed beta, this Pro-tier revenue is intended to make the platform increasingly self-sustaining.
